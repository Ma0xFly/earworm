# public/data

Offline data artifacts shipped inside the extension. They are generated from
local inputs (not committed) by the scripts below and **are** committed here
because they ship with the extension.

| File | Generated by | Source | License |
| --- | --- | --- | --- |
| `ecdict.json` | `pnpm build:ecdict` (`scripts/build-ecdict.ts`) | [skywind3000/ECDICT](https://github.com/skywind3000/ECDICT) via `data/ecdict.csv` | MIT repo (third-party CC-BY ambiguity noted in `NOTICE`) |
| `lemmas.json` | `pnpm build:ecdict` | ECDICT `lemma.en.txt` via `data/lemma.en.txt` | MIT |
| `collocations.json` | `pnpm build:collocations` (`scripts/build-collocations.ts`) | [opensubs-collocations](https://huggingface.co/datasets/vladvlasov256/opensubs-collocations) via `data/en.jsonl` | CC-BY 4.0 — OpenSubtitles, Lison & Tiedemann 2016 |

Input files live in the gitignored `data/` directory. Scripts accept
`ECDICT_CSV`, `LEMMA_TXT` and `OPENSUBS_JSONL` environment variables with
`data/...` defaults.

The content entrypoint fetches these files with
`chrome.runtime.getURL('data/<file>')`; `wxt.config.ts` registers `data/*` as a
`web_accessible_resource` on YouTube origins.

## Dictionary artifacts (`ecdict.json`, `lemmas.json`)

Both files are generated by `pnpm build:ecdict` and are deterministic: no
timestamps, sorted lemma keys, and content-hash `meta.version` values. Re-running
the script on unchanged inputs produces byte-identical files.

### `ecdict.json`

```json
{
  "meta": { "schema": 1, "version": "ecdict-…", "count": 50961, "sourceRows": 770611, "tagged": 14942, "withPhonetic": 42571, "withTranslation": 50961, "withPos": 45449, "withExchange": 28228, "topN": 50000, "maxTranslationChars": 120 },
  "entries": [["look", "luk", "n. 看\nvi. 注意", "n. v.", "zk gk", "p:looked/i:looking/3:looks"]]
}
```

`entries` is a positional array, not an object per word, to keep the shipped
file ~4.7 MB instead of ~7.6 MB. Row positions:

| index | field | notes |
| --- | --- | --- |
| 0 | `word` | ECDICT headword, original case |
| 1 | `phonetic` | IPA without slashes, `""` for the 8.4k words without one |
| 2 | `translation` | Chinese glosses; **real newlines** between senses (up to 2), `[网络]`/`[计]` machine-translation lines removed, clamped to 120 chars (`117` + `...`); if every line was noise, the first line's content is kept without its label |
| 3 | `pos` | coarse POS derived from translation line prefixes (`n. v.`); ECDICT's own `pos` column is empty in every row, so it is never used |
| 4 | `tag` | space-separated exam tags: `zk gk cet4 cet6 ky toefl ielts gre`; every tagged word is retained |
| 5 | `exchange` | raw ECDICT inflection string, `code:form` parts separated by `/`; codes `p` past, `d` past participle, `i` -ing, `3` third person, `r` comparative, `t` superlative, `s` plural, `f` alternative plural, `0` root |

Trim rule: top 50,000 words by `min(frq, bnc)` (0 means unranked) plus every
exam-tagged word. Current output: **50,961 entries**, 14,942 tagged, 4,961,911
bytes.

### `lemmas.json`

```json
{ "meta": { "schema": 1, "version": "lemma-…", "count": 46287, "groups": 84487 }, "map": { "running": "run", "has": "have" } }
```

`map` is a reverse index: lowercase surface form → lowercase lemma headword.
Only lemmas that are ECDICT headwords are kept, and identity mappings are
omitted (`lemmatize` already falls back to the lowercase surface). A form claimed
by several lemma groups is only kept when ECDICT's `exchange` proves one
candidate is its inflected root, which filters noise like `they -> he` while
keeping `has -> have` and `better -> good`. Current output: **46,287 mappings**,
1,013,359 bytes.

### Runtime loading

`src/lib/dict/import.ts` fetches both files through
`chrome.runtime.getURL('data/…')`, parses them (~90 ms for the real data) and
builds an in-memory `Map`, so lookup never waits for IndexedDB. The `earworm-dict`
IndexedDB database (`words` keyed by `word`, `meta` with version/count) is filled
by a chunked (4,000 rows/transaction), resumable import scheduled in an idle
callback; it is skipped when `meta.version` and count already match.
